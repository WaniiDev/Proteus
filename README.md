# Proteus

Proteus is a personal AI companion for the desktop. It is an [Electrobun](https://electrobun.dev) app (Bun backend plus a React webview) built on [Mastra](https://mastra.ai): Mastra owns agent runs, queues, approvals, history, memory, tasks and storage, and the desktop runtime only projects that state to the UI. The app lives in [desktop/](desktop).

## Prerequisites

- [Bun](https://bun.sh) (the package manager and test runner).
- Windows is the product target (Credential Manager, `LocalSandbox` command execution). Tests and typecheck also run on Linux.
- Docker is not needed.

## Setup

```sh
cd desktop
bun install
```

Scripts (from `desktop/package.json`):

| Script | What it does |
| --- | --- |
| `bun run dev` | `electrobun dev --watch`: run the app and rebuild on change |
| `bun run start` | `electrobun dev`: run the app once |
| `bun run hmr` | Vite dev server on port 5173 |
| `bun run dev:hmr` | `hmr` and `start` together |
| `bun run build` | `vite build`, then `electrobun build --env=stable` |
| `bun run typecheck` | `tsc --noEmit` |
| `bun test` | Unit and integration tests |
| `bun run test:e2e` | Playwright end-to-end tests |

> **Note:** `tsconfig.json` maps the `electrobun` imports to `desktop/.hutch/devkit/...`. `.hutch` is generated by the Electrobun tooling and is gitignored, so on a fresh checkout run `bun run build` once before `bun run typecheck`.

## Folder map

`desktop/src/bun` (backend, runs in Bun):

- `index.ts`: Electrobun entrypoint and the RPC boundary to the webview.
- `runtime.ts`: `TextRuntime`, a thin facade that wires Mastra, storage and the services and exposes the methods `index.ts` calls.
- `runtime/`: the services behind the facade (context, thread, provider, workspace, memory, interaction, continuation, run coordinator, message projection, agent factory).
- `core/`: projection, error mapping, diagnostics, Mastra foundation, agent instructions, legacy data cutover.
- `native/`: thin drivers over Mastra's `Agent` (queue, subscribe, suspended runs), stream projection, thread repository, tool-call guard.
- `providers/`: OpenRouter and Codex, auth and readiness, model preferences, credential vault.
- `workspace/`: app workspace, project registry, workspace registry and policy (containment, tool allowlist).
- `memory/`: memory settings, memory tools, scoped durable memory.
- `tools/`: approval and task/plan policies, tool decisions, `ask_user`, working tools.

`desktop/src/mainview` (React UI):

- `components/`: UI components (composer, sidebar, tool timeline, interaction cards, settings panels).
- `hooks/`: React hooks.
- `views/`: top-level views (companion chat, projects, settings).
- `lib/`: RPC bridge, snapshot transport and UI helper logic.
- `orb/`: the companion orb (state, motion, 3D rendering).

`desktop/src/shared`: types and constants shared by backend and UI (`contracts.ts`, `constants.ts`, snapshot codec).

Other: `desktop/e2e` (Playwright), `desktop/scripts` (Electrobun pre-build), `desktop/docs` (design notes), `.agents/skills` (Mastra agent skill).

## Security model

- Contained workspaces: each conversation is bound to the private app workspace or one attached project folder. Roots are chosen by the backend, never the renderer, and path traversal and symlink escapes are rejected.
- Deny-by-default tools: only an explicit allowlist is enabled. Reads run automatically; writes, edits, directory changes, command execution and process termination require user approval.
- Credentials live only in Windows Credential Manager and never enter IPC snapshots, messages, diagnostics or thread metadata.
